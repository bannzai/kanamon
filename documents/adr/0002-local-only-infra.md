# 0002. インフラ構成は完全ローカル (SwiftData) とし、バックエンド・アカウント・Analytics を持たない

## Status
Accepted (2026-08-25)

## Context

決めるべきは DB・ストレージ・ホスティング・認証・Analytics の構成。kanamon は TestFlight のみの個人利用 (ADR 0001) の子ども向けアプリで、保存するデータはゲット状況 (図鑑の進捗) だけ。ユーザー間の共有・サーバー側処理は存在しない。

## Decision

- **DB / ストレージ**: SwiftData によるローカル保存のみ。スプライト等のキャッシュは端末内 (Caches ディレクトリ)。サーバー DB・クラウドストレージは持たない
- **ホスティング / バックエンド**: なし。外部 API は PokeAPI (読み取りのみ) だけ
- **認証**: なし (アカウントレス)
- **課金**: なし (完全無料の個人利用)
- **Analytics / クラッシュレポート**: なし。子どもが使うアプリから外部へデータを送らない

これに伴い、GCP 課金・エラーアラートと Slack 通知チャンネル (お問い合わせ・緊急アラート) の整備は対象外とする (サーバーも問い合わせ導線も持たないため)。

## Consequences

**良い点:**
- 子どものデータが端末の外に出ない。プライバシー対応・運用基盤 (アラート・通知) が不要になる
- 個人利用のスコープに対して実装・運用コストが最小になる

**悪い点 / 引き受けるリスク:**
- 端末変更・削除でゲット状況が消える (個人利用のため許容。惜しくなったら iCloud バックアップを別 ADR で検討する)
- 利用状況の計測手段がない (不要)
