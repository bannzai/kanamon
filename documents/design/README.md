# カナモン デザイン仕様 (改訂版)

bannzai のフィードバック 3 点 (図鑑モチーフ / 学習になる UX + 書く練習 / 動く demo) を反映した改訂版。
静止モックアップ (前版) は破棄し、**動くプロトタイプ 1 ファイル**を成果物とする。

- 動くプロトタイプ: `documents/design/prototype.html` (ブラウザで開くだけで動作。ローカルサーバ不要)
- プロトタイプにポケモンの画像・名前データは含まれない。実行時に PokeAPI から取得する
  (素材をリポジトリに置かない方針は [ADR 0001](../adr/0001-pokemon-assets-testflight-personal-only.md) を参照)

## 1. デザインの土台: ポケモン図鑑モチーフ

アプリ全体を「赤い図鑑デバイスに画面がはめ込まれている」構図で統一する。

| 要素 | 仕様 |
|---|---|
| 筐体 | 赤 (#D93B2B) のグラデーション + 6px の枠 (#33241A) + 角丸 38px + 下方向の厚み影 |
| レンズ | 左上の青い円形レンズ (ハイライト付き)。その右に赤・黄・緑のランプ (赤は点滅) |
| はめ込み画面 | 390×844 を基準。内側に薄赤のインナーシャドウで「はめ込み感」を出す |
| 番号 | 全モンスターに `No.001` 形式の 3 桁番号。ずかんのセル左上と各画面のヘッダーに出す |
| 未ゲット | 画像を `filter: brightness(0) opacity(.34)` でシルエット化し、名前は `？？？`、背景は砂色 |
| ゲット演出 | 放射状の光 + 紙吹雪 + 中央のバッジ + 斜めの「とうろく」スタンプ |

子ども向けの明るさは維持する: 画面の中身は従来どおりクリーム地 + 原色 + 太い枠 + ぼかさない影。

## 2. 画面一覧と遷移

```
ホーム
 ├─ ずかん          … 一覧 → セルをタップ → よみれんしゅう (その 1 匹)
 ├─ よみれんしゅう   … 1 文字ハイライト読み上げ / 文字タップで 1 音
 ├─ かきれんしゅう   … 書き順の番号 + 矢印 → なぞり → 全文字でゲット
 ├─ クイズ          … 3 種類を順番に出題 → 正解でゲット
 ├─ なまえ づくり    … 文字を選んで名前を組み立てる → 正解でゲット
 └─ もじ ずかん      … 五十音表。出会った文字が埋まる
                       文字をタップ → その文字を含むポケモン一覧 → よみれんしゅうへ
```

全画面から左上の戻るボタンでホームへ。よみれんしゅう・クイズは左右スワイプでも送れる。

## 3. 「学習」になる読み練習

「絵と名前を眺めるだけ」を避け、カタカナの読みが身につく作りにする。

### よみれんしゅう
- **1 文字ずつのハイライト + 読み上げ**: 「ぜんぶ よむ」で先頭から 1 文字ずつ黄色く浮き上がらせ、その文字を読み上げる。読み終わってから次へ進むので音と光が一致する。最後に全文字を光らせて名前全体を通しで読む
- **文字の個別タップ**: どの文字でもタップでその 1 音だけ再生。読めない文字だけを繰り返し確認できる
- **カタカナとひらがなの対応**: 各文字の下に対応するひらがなを小さく青字で並べる。ひらがなは読める子が、カタカナを「知っているひらがな」に橋渡しして読める
- **にている もじ の注意**: シ/ツ・ソ/ン・ク/ケ・ス/ヌ・マ/ム・ナ/メ・ハ/ヘ・チ/テ を対象に、該当文字を赤枠で示し、タップすると見分け方を出す (例: 「シ は てんてん が よこむき  ツ は てんてん が たてむき」)

### もじ ずかん (五十音表)
- 五十音 46 文字を 5 列の表で並べ、**出会った文字だけが色付きで埋まる**。未習の文字は砂色のまま
- ポケモンを集める体験を文字にも適用し、「どの文字がまだ読めないか」が一目で分かる
- **文字をタップすると、その文字が名前に入っているポケモンの一覧が下からシートで出る** (逆引き)。名前の中の該当文字は赤字 + 黄色の下線で示し、どこにその文字がいるかを見せる。未ゲットはシルエット + 「？？？」のままにしてネタバレを避ける。ゲット済みの行をタップするとそのポケモンのよみれんしゅうへ飛ぶ
- 文字をタップした時はその音も再生する
- 濁点・半濁点・小文字は元の文字に合算する (ピ→ヒ、ャ→ヤ)。46 文字の達成を目標にする

### クイズ (3 種類を順番に出題)
| モード | 問い | ねらい |
|---|---|---|
| 4 たく | 絵 → 名前を 4 択 | 名前の全体を形として捉える |
| あなぬけ | 名前の 1 文字が `？` で、候補 4 つから選ぶ | 1 文字単位の弁別。にている文字が選択肢に混ざる |
| なまえ から え | 名前 (文字) → 絵を 4 択 | 逆方向。文字から音・意味を引ける |

正解で「ゲット！」、不正解はボタンが揺れて「もう いちど」と促すだけで先へ進まない (減点や失敗表示はしない)。

## 4. かきれんしゅう (新画面)

名前の各文字を 1 文字ずつなぞって覚える。

### 画面構成
1. 上部にモンスターの小さな画像と、名前の文字を横一列に表示 (現在の文字が光る / 書けた文字は緑)
2. 中央になぞり面 (109×109 の正方形、十字のガイド線入り)
3. 下部に「かきじゅん を みる」と読み上げボタン

### 動き
1. **書き順の番号 (常時表示)**: 最初から全画に ①②③ の番号を出す。番号は画の書き出し位置から進行方向と逆に 10 ずらして置き、線と重ならないようにする。今なぞる画の番号だけ黄色で脈打ち、書き終わると灰色になって次へ移る (KanjiVG は番号座標も持つが、始点から自前で算出する方が確実)
2. **進行方向の矢印 (常時表示)**: 今なぞる画の上を、赤い三角が始点から終点へ書き順どおりに移動し続ける。終点まで行くと約 0.4 秒休んで始点から繰り返す。カーブでは進行方向に合わせて向きも回転させる (`getPointAtLength` で 1.2 先の点との角度を取る)。速度は画の長さに比例 (最低 900ms)
3. **書き順アニメーション**: 「かきじゅん を みる」で、青いストロークが 1 画ずつ順番に描かれていく (`stroke-dasharray` を使ったストローク長ベースのアニメーション)
4. **なぞり**: 薄いグレーで全画をお手本表示。指でなぞると緑の線が追従する
5. **判定 (緩め)**: 次の 3 条件をすべて満たせば成功とする
   - 始点が、その画の書き始めから半径 30 以内 (109 座標系)
   - 終点が、その画の書き終わりから半径 32 以内
   - 画の経路上の 27 点のうち **72% 以上**が、なぞった軌跡の半径 26 以内を通っている
   - 失敗しても画は消えず、面が横に揺れて「もう いちど  やじるし に そって ゆっくり なぞろう」と促すだけ。回数制限・減点はしない
6. 1 画書けると濃い線で確定し、番号と矢印が次の画へ移る
7. 全画書けたらその文字を読み上げ、自動で次の文字へ
8. **全文字書けたらゲット**: ずかんに登録し、ゲット演出を出す (クイズと同じ扱い)

赤い始点マーカー (●) は矢印と役割が重複するため置かない。番号の丸自体が「ここから」の目印になる。

### 進捗保存の考え方
`SwiftData` に次の 3 つを永続化する。demo ではメモリ上の `Set` で同じ構造を再現している。

| 保存するもの | 型 | 使いみち |
|---|---|---|
| ゲット済みモンスター | `Set<Int>` (図鑑番号) | ずかんの表示・進捗 |
| 読めた文字 | `Set<Character>` | もじ ずかんの埋まり具合 |
| 書けた文字 | `Set<Character>` | かきれんしゅうの「書けた」表示 |

- 文字は濁点・小文字を元の文字に正規化してから記録する
- 読み上げ・なぞり成功のたびに追記する (減ることはない)
- モンスター単位ではなく**文字単位**で持つことで、別のモンスターの名前で同じ文字に出会っても進捗が引き継がれる

## 4-2. なまえ づくり (新画面)

絵を見て、文字を 1 つずつ選んで名前を組み立てる。読み (文字の弁別) と綴り (並び順) を同時に扱う。

### 画面構成
1. 上部にポケモンの画像
2. 中央に名前の文字数ぶんの空きマス (破線)
3. 下に文字タイルの一覧 (正解の文字 + ダミー 3〜6 文字をシャッフル)
4. 最下部に「1 つ戻す」と「よんで もらう」

### 動き
- タイルをタップすると先頭のマスから順に埋まり、そのタイルは薄くなる (同じ文字が名前に 2 回出る場合に備え、使用回数で管理する)
- 埋めたマスをタップすると、そこから後ろを取り消せる
- 全マスが埋まった時点で判定する。**間違っていた場合は全部消さず、先頭から合っている位置までを残して戻す** (子どもが最初からやり直しにならないようにする)
- 正解すると先頭から順にマスが緑に光り、ゲット演出へ進む
- 「よんで もらう」で名前を読み上げる。音を聞いてから文字を探す遊び方もできる

### ねらい
クイズの「あなぬけ」が 1 文字の弁別なのに対し、こちらは**名前全体を自分で構築する**。ダミー文字が混ざるので、似ている文字の選び分けがそのまま練習になる。

## 5. データの取得元 (実行時取得・リポジトリに置かない)

| データ | 取得元 | 備考 |
|---|---|---|
| 日本語名 | `pokeapi.co/api/v2/pokemon-species/{id}` の `names` から `ja-hrkt` | カタカナ表記 |
| 画像 | `pokeapi.co/api/v2/pokemon/{id}` の `sprites.other.official-artwork.front_default` | |
| 書き順 | KanjiVG `raw.githubusercontent.com/KanjiVG/kanjivg/master/kanji/{5桁hex}.svg` | 例: ア = `030a2.svg`。CC BY-SA 3.0 (Ulrich Apel) — 表示に帰属を出す必要あり |
| 読み上げ | Web Speech API (`ja-JP`) | iOS 実装では `AVSpeechSynthesizer` に置き換える |

ひらがな変換はコードポイント演算 (カタカナ − 0x60) で行い、変換表を持たない。

**注意**: KanjiVG は CC BY-SA 3.0 のため、帰属表示が必要。またライセンスの継承条件があるため、同梱するか実行時取得にするかは実装前に判断が要る。方針の決定は https://github.com/bannzai/kanamon/issues/19 で行う。

## 7. iPad での拡大方針

390×844 を基準に作り、iPad では次のように扱う。

- **画面の中身は横に引き伸ばさない**: 最大幅 (目安 520pt) で中央寄せし、左右は図鑑の筐体色で埋める。図鑑デバイスを大きく持っている見え方になり、文字の行長も子どもが追える範囲に収まる
- **なぞり面だけは拡大する**: かきれんしゅうの正方形は使える高さいっぱいまで大きくしてよい (指が大きく動くほど書きやすいため)。判定は 109 座標系の相対値なのでサイズが変わっても閾値は同じ
- **ずかんのグリッド**: 3 列固定ではなく、セル幅 110〜130pt を保ったまま列数を増やす (iPad で 5〜6 列)
- 文字サイズは変えない (拡大すると幼児には却って追いにくいため)
